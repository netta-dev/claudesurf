# Architecture

## Modules

- **`server/server.js`** — MCP stdio bridge, one per Claude Code session. Validates calls with `dispatch.js`, POSTs `{sessionId, tool, action, args, env}` to the daemon over the `0600` Unix socket, renders the envelope with page text inside the nonce delimiter, and maps its own failures onto outcomes (unreachable daemon → `setup_error`, request timeout → `error`). `sessionId` comes from `CLAUDE_CODE_SESSION_ID` so a respawned bridge reuses its window.
- **`server/daemon.js`** — one per OS user: the HTTP server on the socket, the action handlers, and `ensureBrowser` (coalesced launch; retains the last request's graphical environment).
- **`server/dispatch.js`, `envelope.js`, `diagnostics.js`, `paths.js`** — loaded by both: the action table with validation and tool definitions, the outcome vocabulary, the leveled stderr logger (journald `<N>` prefixes under `JOURNAL_STREAM`), and the socket, profile, and record paths with their overrides plus the graphical-variable allowlist the bridge forwards.
- **`server/cdp.js`** — the protocol client: NUL-delimited JSON over the pipe's fds 3 and 4, id correlation, `sessionId` routing, event fan-out, timeouts and deadlines, EOF and pipe error both as close.
- **`server/browser.js`** — binary lookup, graphical environment, launch and handshake, the browser record, orphan reap, `enableTargets` (auto-attach and download denial).
- **`server/sessions.js`** — `Session` records (window, identity and working targets, label, queue, notes, ref sets, page-opened targets) and the target registry (type, window, generation, isolated worlds per frame, load and navigation counters, dialogs, and for an iframe target its frame number and parent). Window creation and repair live here.
- **`server/read.js`** — `page` (the unit pipeline, the frame units, the ref sets, the hidden list), `info`, `screenshot`. **`server/input.js`** — `navigate`, `click`, `scroll`, and a ref's resolution with its staleness rules; the grammar is `dispatch.js`'s, which both processes load. **`server/action-support.js`** — what both share: `OutcomeError`, the state lines, the working-target lookup, the http check, the page-state read, the page-script sources, and `LABEL_MAX`.
- **`server/snapshot.js`** — one `Accessibility.getFullAXTree` answer read as controls, landmarks, named groups, iframe nodes, and a scope root, plus the omission report. Pure over protocol data. **`server/render.js`** — the daemon side of a render (descriptors, the pipelined resolves, one call per unit) and the assembly: frames inlined, `find`, the links index, the header lines, the paging cut.
- **`server/page/*.js`** — page-side scripts (render, walk, click, scroll) run in the browser and sent as source; never `require`d. `state.js` holds the one definition of hidden, disabled, and masked, and is spliced into `render.js`, `walk.js`, and `click.js` at their `// @include state.js` line by `action-support.js`. `render.js` runs after the three libraries (Readability, Turndown, its GFM plugin), which `action-support.js` reads from `node_modules` and concatenates with it.
- **`server/static/session.html`** — the session page both tabs start on, addressed by `file://`; role, session id, and start time in the URL fragment; `render(name, description)` for the label; two `target=_blank` links to itself that the daemon clicks to open the other role's tab.

## Request flow

`validate` → `ensureBrowser` (one launch for a burst of first calls) → `sessions.ensure(sessionId)` (serialized per session, creates or repairs the window) → the handler under the session's queue → notes and dismissed-dialog lines added → envelope. The bridge times out at 35 s; the daemon runs every request under a 33 s deadline (launch 15 s, window creation 5 s, `navigate` load ≤ 25 s or what remains minus 2 s).

## Reading a page

A read is a pipeline over units. A unit is one document the daemon can pull a tree from and run script in: the page's main frame, a same-process child frame (the page target plus a `frameId`), or an out-of-process child frame (its own iframe target). Per unit: one `Accessibility.getFullAXTree`, one `DOM.resolveNode` per control, landmark, group, iframe, and scope root under an object group released in a `finally`, one `DOM.describeNode` per iframe node for the frame it holds, and one `Runtime.callFunctionOn` on `claudesurfRender` in the unit's isolated world. The page script builds an annotated clone (hidden elements out, a wrapper clipped to an empty box included; an element that paints nothing of its own — a `display:contents` wrapper, a slot, a float-only container whose children paint outside it, a control among them — is descended instead of judged; open shadow roots flattened, `data-cs-ref` stripped off every clone and then stamped on the described nodes), optionally hands it to Readability, and runs Turndown over it. The markers come from the descriptors the daemon sent and key on a ref the clone walk stamped, their fields escaped in the brackets and backslashes Turndown escapes in text and their URLs percent-encoded in those brackets, the parentheses, and whitespace, so neither page text nor a `data-cs-ref` the page wrote can close a marker or pose as one; a link's own text, or the name it falls back to, gets a backslash ahead of a leading token the ref grammar matches for the same reason, since the bracket there is the link's own rather than page text Turndown escaped. Page text reaches all of that stripped of the two characters the renderer reserves — the frame placeholder's NUL, and the private-use filler that pads a control Turndown would drop for being blank and that the finished markdown is stripped of — so a page can neither forge a placeholder nor hide a ref token from the guard. A `<pre>` no marker has to reach renders as a fenced block, opened past the longest backtick run it holds, with a code block's language taken from a restricted pattern, since a fence line carries no escapes; one holding a described node renders as the block it is instead.

`read.js` then reads the frames inside what rendered, one level at a time, at most eight units over at most three levels, each under its own 5 s budget and degrading to `[e40 frame url (not readable)]` rather than failing the read — a frame whose own document changed between its tree pull and the end of its render degrades the same way, since nothing it rendered belongs to the tree it was rendering; a same-process frame's own navigation moves no generation the caller can check, so `render.js` treats every resolved node coming back null over a non-empty descriptor list as that same signal; a frame past either limit renders `[e40 frame url (not read: frame limit)]`. Each frame's output replaces the `\u0000frame:<ref>\u0000` placeholder its parent left, capped at 8,000 characters per frame and 16,000 per read; a frame with no placeholder of its own in what the parent rendered — Readability dropped the `<iframe>`, or the rule for a link or a control around it discarded the placeholder with the rest of that element's content — is never read, and the omission line names it under `frames not read`. The page unit has no fallback: its failure is an `error` naming the exception and the recourses. The hidden-control count and the `hidden=true` list come from `walk.js` over the page target's whole document, the one thing the walk still serves; the walk judges hidden as the clone walk does, the boxless carve-out included, and caps and escapes each label as the daemon's cap does a name, since the list brackets a ref of its own.

## Targets and attach

`Target.setAutoAttach` runs with `flatten` and `waitForDebuggerOnStart` for `page` and `iframe` targets, at browser level for pages and again on every page and iframe attach, the per-target call that surfaces out-of-process child frames. An iframe target is recorded like a page (`Page.enable`, the release, no focus emulation and no window lookup) with `type: 'iframe'`, the parent target whose protocol session carried its attach, and a frame number from its root page's counter that is never reused. The attach handler records the target, queues `Browser.getWindowForTarget`, `Page.enable`, and `Emulation.setFocusEmulationEnabled`, sends `Runtime.runIfWaitingForDebugger`, and only then awaits the queued commands: awaiting first deadlocks on a noopener-opened tab, whose `Page.enable` answers only after the commit the pause holds back. A target whose URL is the session page with `#role=<identity|working>&session=<id>` is claimed for that role, at attach or on its first main-frame `Page.frameNavigated` (or from `Page.getFrameTree` when the attach carried no URL); otherwise a target with an `openerId` owned by a session is recorded as page-opened under that session; anything else stays unowned.

## Session windows

`Target.createTarget({newWindow: true, background: true})` opens the session page as the working tab. The identity tab is opened from it by Ctrl-clicking the page's identity link with real mouse events (`modifiers: 2`), which yields a background tab, so the working tab stays active. Repairs on the next `ensure`: working tab gone and identity page intact → a scripted `userGesture` click on the identity page's working link (a foreground tab, in whatever window the identity tab now sits); working tab gone and identity tab gone or navigated away → the whole window recreated under the retained label; identity tab gone alone → left absent; identity tab failed at window creation while the working tab came up → reopened in place from the working tab's link on the next `ensure` (note "identity tab was recreated"), or left absent when that fails again or the working tab has left the session page (note "identity tab could not be recreated; it returns with the next window"). Pipe EOF drops every window and target; labels survive.

## Refs and worlds

A ref is `e<backendDOMNodeId>`, or `f<n>e<id>` for one read inside the iframe target numbered `n` under this page; backend ids are unique per renderer, so the prefix says which renderer's. Each session keeps a `{generation, ids}` per target, where `ids` maps each id a read found at that generation to the frame it was read in (`null` for the target's own main frame), so a node resolves in its own frame's world. A read fills the set from every control, group, landmark, and iframe node of each rendered unit's tree, whether or not the marker was delivered, and stamps it with the generation of the unit's own target, taken before that unit's tree was pulled; a read that a navigation overtook leaves nothing the new document can resolve against. A click against a set of another generation returns `stale_ref`, as does an `f`-ref whose frame target is gone or has moved on; an id the set lacks, or one that no longer resolves, returns `error`. A trusted click on an `f`-ref is refused; on a bare ref of a same-process frame it resolves both the element and the node its hit test found in that frame's world, the world `Runtime.callFunctionOn` compares them in.

Every page-side script runs in one isolated world per target, frame, and generation (`Page.createIsolatedWorld`, world name `claudesurf`), recreated once when a command reports the context missing; the world record carries whether the renderer's libraries have been evaluated in it, so a second read of the same document skips the 140 KB. The one main-world call is `render` on the session page.

## Dialogs, clicks, downloads

`Page.javascriptDialogOpening` is answered at once (`accept: false`, `beforeunload` accepted) and queued on the target; the daemon appends `Dialog (<type>): <message>` to the next payload, `message` made safe the way page text elsewhere in a payload is: one line, capped, brackets and backslashes escaped. After a click the daemon waits up to 300 ms for `Page.frameStartedNavigating` with a cross-document `navigationType`, then up to 10 s (cut to 2 s before the request deadline) for the load event; `Page.downloadWillBegin` ends the wait, since a denied download never commits. The waits are event-driven (`Sessions.waitUntil`, notified on every counted event). A load that misses the wait reports `Navigated: started`. A target attributed to the session during the wait is reported as a tab (same `windowId`) or a popup.

## Storage

Persistent state is the Chrome profile directory and the browser record beside the socket (`<socket basename>.browser.json`, `{pid, startTime}`): written at launch, cleared on pipe close, left in place on daemon exit. The next daemon reaps the recorded browser if it outlived its pipe and otherwise clears the record.

## Non-obvious gotchas

- `Input.dispatchMouseEvent` raises the session window; so does any page-initiated target creation. Scripted clicks, keys, navigation, and screenshots don't.
- Input into a tab that is not its window's active tab stalls about 5 s per event without `Emulation.setFocusEmulationEnabled`; every attached page target gets it.
- `Runtime.enable` and `DOM.enable` are never sent: everything used works without them, and `Runtime.enable` is detectable by page script.
- `document.visibilityState` reports `visible` on both tabs in headful, so it can't tell the active tab; the X window title can. A screenshot of the inactive tab takes about 3 s and later ones can time out.
- Chrome exits when the pipe closes, so a daemon exit takes the browser with it; the record and reap path covers the case where it doesn't.
- `Page.enable` on a paused noopener-opened tab answers only after the release. Every command queued at attach is settled together, since a wedged renderer fails several and an unawaited rejection would end the daemon.
- An out-of-process frame's target id equals the `frameId` its `<iframe>` element reports, and its own main frame carries a `parentId`; both are observed, not documented.
- `Page.javascriptDialogOpening` arrives on the page target's session whichever frame raised the dialog; the daemon drains the frame targets' queues as well.
- `Target.targetInfoChanged` needs `Target.setDiscoverTargets`, which is not enabled; URL changes come from `Page.frameNavigated`, whose `frame.url` omits the fragment (`frame.urlFragment` carries it).
- `Page.frameStartedLoading` also fires for pushState; `Page.frameStartedNavigating` carries the `navigationType` that tells them apart.
- `--no-startup-window` plus the pipe keep Chrome alive with zero windows.
- Exit code 21 before the handshake means the profile is held by another instance.
