## A. Human triage overrides

1. The implementer was told to land the LLD's five sub-commits itself; each subagent `git commit` raised a permission prompt, and the human denied one, which stopped the run with 1.2–1.5 uncommitted. The orchestrator then committed them by hand.
   - [-] Resolution: FOLD — into A4, which carries the same rule.

2. The implementer's context hit ~308k tokens in one phase, past the human's 200k reuse cap. The cap is a session instruction; the build playbook's fix loop ("fix passes reuse the implementer's pick") assumes an unbounded reuse.
   Phase 2: the orchestrator split the six sub-commits into two implementer runs (2.1–2.3, 2.4–2.6) to stay under the cap; run 1 still used ~407k tokens (135 tool calls, 42 min), so a split at sub-commit boundaries does not bound a run. Fix passes for phase 2 go to fresh implementers with the finding list, not the original run.
   Phase 3: four runs by dependency layer. Run 1, the smallest slice (moves and leaf modules), used ~440k tokens (203 tool calls, 31 min) against a brief that said to stop near 350k, so a token stop rule in a brief didn't bind. Run 2 (the gate) used ~472k (191 calls, 43 min), run 3 (settling, the change summary, overlays) ~716k (393 calls, 75 min), and run 4 (the actions, wiring, and docs) ~524k (277 calls, 54 min), with four subagents of its own.
   - [x] Resolution: SKIP — `build.md` already sends each fix pass to a fresh implementer (`/implement` mode `fix`; "the implementer's pick" is its model and effort), so it reuses no agent. The phase-3 runs show that neither a smaller slice nor a stop rule in the brief bounds a run (440k tokens on the smallest slice), so a playbook rule can't hold a fresh run under 200k.

3. Approved skip: the reviewer flagged the `package.json` 1.0.0 → 2.0.0 bump as unsanctioned by the LLD. Kept; the phase deletes the extension and replaces the tool surface. An LLD that changes a package's public surface could name the version bump so a reviewer doesn't have to guess.
   - [-] Resolution: HANDOFF — the LLD template doesn't ask for it. In `~/.claude/playbooks/lld.md` §Template, under `## Files`, add the instruction line "*When the phase changes a package's public interface, name its version bump under Modified.*"

4. Phase-2 build: the orchestrator planned to let the implementer land the LLD's six sub-commits itself because bypass-permissions was active. The human overruled: a commit always goes through her, permission mode notwithstanding, and only after she reviews and approves the full implementation. Candidate: build.md and implement.md state that an implementer never commits; sub-commits an LLD names are landed by the orchestrator after approval.
   - [-] Resolution: HANDOFF — `implementer.md` already says "Don't commit — the caller commits after reviewer + human approval"; no step says who lands the sub-commits that a design names. In `~/.claude/playbooks/build.md` step 12, append: "When the design names sub-commits, land them yourself, in its order, after her approval at step 10."

## B. Deferred implementer observations

   - [x] Resolution: SKIP — in place: `reviewer.md`'s test-coverage axis names, for each behavior the design changes, the test that fails if it's reverted, and `build.md` step 4 ends with the mutation-checker.

6. Phase-2 build: every implementer fix pass flagged that its standing rule forbids editing `docs/designs/` while the brief asked for LLD corrections in place, and did them anyway. Candidate: implementer.md says design-doc corrections are in scope when the brief names them, so the flag stops recurring.
   - [-] Resolution: FOLD — into B4: the orchestrator applies design-doc corrections at `build.md` step 11, so a fix-pass brief stops asking the implementer for them and the rule stands.

7. Phase-2 build: the review loop ran eleven rounds and twelve fix passes (~6M subagent tokens). Each round found one or two real correctness items in the same class — a page-controlled string reaching the payload unescaped (names, values, alt, option names, URLs, frame URLs, hidden labels, article title and byline, the `Title:`/`URL:` lines, a page-set `data-cs-ref`, a `<pre>` closing its own fence) — plus a majority of test-coverage findings (assertions that could not fail). Candidates: (a) an LLD whose output carries page-controlled text lists every such field and its sanitizer as one table, so review checks a list instead of discovering one field per round; (b) the implementer brief requires a mutation check per correctness test (revert the fix, see red) — the later passes did this on request and it cut the vacuous-test findings. After the Opus loop converged, one Fable (`high`) pass found three must-fix defects and its re-verify two more, all in the same class; the Opus rounds had reported "no findings" on that surface. Candidate (c): the build playbook's final Fable pass is the default for a change with a page-controlled-text surface, not an offer. Phase 3 repeated the pattern: after eight Opus rounds, the final Fable (`high`) and Codex Sol (`xhigh`) pass found eleven correctness findings between them. Among them were a working tab left outside the domain gate, an empty `select` value refused, a retained-render cap that skipped the link lists, and a `tabs new` close that left no working tab. Codex and Fable overlapped on two findings only.
   - [x] ==†==[^1] Resolution: HANDOFF — candidate (a) alone. `~/.claude/playbooks/lld.md` §Process, new step 7 after Field-semantics changes: "**Untrusted text.** When the plan puts untrusted text (a web page's, a user's, a third party's response) into output that a reader parses, list each field and its sanitizer in one table in Design."

8. Phase-2 build: two reviewer rounds delivered only an addendum from a delegated sub-audit, the main report lost; the orchestrator had to ask for a resend each time. The brief already said "report once, in one message"; the reviewer still spawned sub-audits and timers. Candidate: reviewer.md forbids background timers and requires the final message to be the complete report.
   - [x] Resolution: SKIP — in place: `reviewer.md` has it wait for its sub-passes by ending its turn, never a sleep loop, and report once, as one list, after all have returned.

9. Phase-3 run 4: the implementer and one of its subagents red-checked by mutation in the same working tree at once. The implementer's backup of `sessions.js` caught the subagent's mutation in place, so its restore put the mutation back; the subagent noticed and restored the file. Candidate: an agent that red-checks while another agent shares the tree runs its mutations in a private copy of the tree, as the orchestrator did for the phase-3 baseline fix, or the brief forbids parallel red-checks.
   - [-] Resolution: HANDOFF — `~/.claude/agents/implementer.md` §Behavior, after the delegation bullet: "A subagent you delegate to runs its red-checks and mutation checks in its own copy of the tree (`git worktree add`), or leaves them to you."

10. Phase-3 build: comment and doc prose took a large share of every review round. Round 1 listed about 30 comment sites, and the fix pass's sweep fixed about 180. Round 2 still listed about 60 more (no-negation, garden paths, noun-phrase openings, stale pointers) and 11 doc-accuracy findings. The build playbook runs the comment review (step 6) only after the review loop converges, so each code-review round re-litigates prose. Candidate: run the comment-review pass once before the first code review, and tell the code reviewer to leave comment prose to that pass, keeping comment findings that mislead about behaviour.
   - [-] Resolution: HANDOFF — the comment review at `build.md` step 6 already covers comment prose; the reviewer re-flags it each round because its in-file structure axis says comments always follow `prose.md`. Moving the reviewer off it removes the overlap without a second comment pass.
     a. `~/.claude/agents/reviewer.md` §Don't flag, new bullet: "The prose of a comment or docstring, which `build.md` step 6's comment review owns. Flag a comment that misstates the code, and one that cites a design doc, decision number, or review round."
     b. Same file, in-file structure axis: replace "Comments and prose always follow `conventions.md` / `prose.md`." with "Markdown prose follows `prose.md`."

11. Phase-3 build: every implementer brief ran the headful gate, which opens Chrome windows on the human's display. In fix pass G1 it ran while the human was playing a game there, and a window-focus check failed twice because the game held the active window. Candidate: a fix pass runs the headless gate only; the headful gate runs once, at the full-suite step, after the orchestrator asks the human whether the display is free.
   - [x] Resolution: in `.claude/context/capabilities.md`, append to the **test** line: "A fix pass runs it without `CLAUDESURF_LIVE_HEADFUL`; the headful run comes once, at `build.md`'s full-suite step, after asking the human whether the display is free."
   - [-] Resolution: HANDOFF — any suite that opens windows on the human's display has the same hazard. `~/.claude/playbooks/build.md` step 4, Full suite: append "When `capabilities.md` marks part of the suite as using the human's display, ask her whether the display is free before running that part, and leave it out of fix passes."

12. Phase-3 build: the `Navigated:` verdict took a correctness finding in three review rounds running (round 2's M28, round 3's M40, round 4's M49 and M50). Each fix pass patched the last fix with one more mark, and each patch opened the next case. Round 4's triage replaced the marks with one table of tab states and verdicts, judged once. Candidate: when a review round finds a bug in an earlier round's fix to the same logic, the triage writes the logic out whole (a table of states against outcomes, one test per row) and the fix pass rewrites it against the table instead of patching.
   - [-] Resolution: HANDOFF — `~/.claude/playbooks/build.md` step 4, new bullet after Re-review: "**Repeat findings.** When a round finds a bug in an earlier round's fix to the same logic, write the logic out whole as a table of states against outcomes, and have the fix pass rewrite the logic against the table, with one test per row."

13. Phase-3 build: on a 13,000-line diff the review loop didn't converge on test coverage. Rounds 5 and 6 found three coverage gaps and none, then a fresh round-7 reviewer mutation-tested code that every earlier round had passed and listed 30 more (operators, boundaries, unpinned head lines). Each fresh reviewer samples different corners by hand, so coverage findings keep arriving at a rate the loop can't drain. Candidate: run a mutation-testing tool (Stryker for JavaScript) over the changed files once the implementation lands, give the surviving mutants to the implementer as one list, and keep the review rounds for correctness and design. The human ended the phase-3 loop with one round (round 8) scoped to correctness and the work changed since round 6, with coverage gaps outside that scope left to a follow-up. Phase 4 repeated it on a 5,000-line diff: rounds 6–8 found no must-fix, then the final Fable (`high`) and Codex Sol (`xhigh`) pass listed 46 findings, about 30 of them behaviours the LLD specifies that no test pins (a removed guard or a changed constant left the suite green), beside four real races.
   - [x] Resolution: HANDOFF — `build.md` now runs the mutation-checker, but only after the final pass, so the review rounds still hunt coverage gaps by hand, and the checker mutates by hand too.
     a. `~/.claude/playbooks/build.md` step 4: run the mutation check once before the first review round as well, and fix its survivors in the first fix pass; the end-of-loop check then covers what the fix passes changed.
     b. `~/.claude/agents/mutation-checker.md`: "When `capabilities.md` declares a `mutation_test` command (Stryker for JavaScript, mutmut for Python), run it on the changed files and report its survivors; otherwise mutate by hand."

Stryker 10.1.1's TAP runner drives the `node:test` files, and its baseline run over the 793 unit tests took about 43 s with per-test coverage, so mutation runs would be fast enough. But two tests that relaunch the fake Chrome on one profile, one in the sessions tests and one in the browser tests, fail inside Stryker's runner while they pass under `node --test`, and a failing baseline stops Stryker before it tries a mutant. The cause is undiagnosed.
     Title: "claudesurf: declare a Stryker `mutation_test` command"
     Description: "Find why the fake-Chrome relaunch tests in `sessions.test.js` and `browser.test.js` fail under Stryker's TAP runner though they pass under `node --test`, and fix them. Then add `@stryker-mutator/core` and `@stryker-mutator/tap-runner` as dev dependencies in a root `package.json`, since a Stryker sandbox of `server/` alone would leave the tests in `test/` loading the unmutated files, and declare `mutation_test` in `.claude/context/capabilities.md`."

## D. Design-review loop

1. The phase-2 LLD took five design-review rounds; rounds 2–4 each found real gaps that a check of the draft against the shipped code's seams would have caught before dispatch — an error class the daemon maps by `instanceof` from one module (`SetupError`), a shared object-group name across units on one protocol session, an attach handler's early return for non-page targets, a per-read frame index against phase 1's "refs stay valid within a generation" promise. Candidate: before the first review dispatch, the LLD author walks each new mechanism against the module it plugs into (error mapping, handler early-returns, shared names, prior-phase promises) and records the check in the doc's Context block.
   - [-] Resolution: HANDOFF — `~/.claude/playbooks/lld.md` §Process, new step 8 after B7a's: "**Seams.** Before the first review, walk each new mechanism against the module it plugs into: how that module maps errors, where its handlers return early, which names its callers share, and what earlier phases promised about it." The record in the Context block is left out, since it would add text that review then has to read.

2. The phase-4 LLD took seven design-review rounds. Round 5's S60 noted that a restarted daemon doesn't tell the agent its cursors went stale, and the fix added a restart note on each session's first call; round 6 found the note false for every session that started after the restart (M20), and the fix removed it. Round 3's S35 and round 4's S58 changed shipped modules (`requests.js`'s lifecycle, `browser.js`'s record) to close gaps a risk line could have carried. Design-doc.md §G2 already asks for the smallest change that settles a finding. Candidate: from round 3 on, a finding about a residual edge case gets a risk line by default, and a new behaviour or a change to a shipped module only when the finding is a must-fix.
   - [x] Resolution: HANDOFF — `~/.claude/playbooks/design-doc.md` §G2, append: "From the third round on, and in the final pass (§G5), settle a finding about a residual edge case with a risk line; add behavior or change a shipped module only for a must-fix."

3. The phase-4 LLD's Codex prose pass grew the doc from about 560 to 845 lines (lists, Rationale callouts, footnotes). It moved a binding build rule (the headful run's timing) into a collapsed Context callout, and moved a system fact (the phase completes the action inventory) into the Context block. The LLD was a new file, so `git diff` showed it whole, and checking the pass meant rereading the doc. Candidate: snapshot a design doc before each prose pass (`cp` to `/tmp`) and review the pass with `diff`; tell the Codex prose pass that a sentence binding the implementer stays in main text.
   - [-] Resolution: HANDOFF — `~/.claude/playbooks/design-doc.md` §G4:
     a. Before "After both, read `git diff`", add: "Before each pass, copy the doc to `/tmp`, and review the pass with `diff` against that copy, since `git diff` shows a new doc whole."
     b. After "told to apply each finding's rewrite", add: "Tell both passes that a sentence that binds the implementer stays in the main text, outside any callout."

4. After the phase-4 LLD's seven review rounds converged, the final Fable (`xhigh`) and Codex (Astra `xhigh`) passes found five must-fix defects between them: a loader id that a silent first commit never records, a response-field rule that a neighbouring reCAPTCHA v3 token could satisfy, a handoff that two overlapping calls of one session could leave open, a decision pointer to the wrong phase-3 decision, and two fixtures written as changes to routes that don't exist. Two scoped rounds followed, one of which reverted a final-pass refinement (keeping the urgency mark across a re-opened handoff) that left the mark's clear without a trigger. B7(c) records the same pattern for code review. Candidate: the final pass is the default for an LLD that adds mechanism, not an offer, and a final-pass suggestion that adds behaviour gets the same risk-line-first rule as D2.
   - [-] Resolution: HANDOFF — `~/.claude/playbooks/design-doc.md` §G5, after "Never auto-run.", add "Recommend it when the doc adds mechanism." The offer stays an offer, as B7b keeps it for code; D2's rule covers the final pass's suggestions.
